# Checklist de fin de session

Avant de considérer une session technique terminée :

1. Mettre à jour Airtable uniquement avec des faits prouvés.
2. Distinguer clairement :
   - code ajouté ;
   - CI verte ;
   - fusion dans `main` ;
   - déploiement ;
   - test runtime ;
   - activation LIVE.
3. Si une PR historique est remplacée, la fermer ou la marquer superseded.
4. Ne laisser qu'un chemin canonique par capacité.
5. Mettre à jour `WORK_STATE.md` si l'état global a réellement changé.
6. Mettre à jour `CURRENT_BLOCKERS.md` uniquement si un verrou a disparu/apparu.
7. Ne jamais inscrire de secret, token, cookie, mot de passe ou URL signée.
8. Ne jamais déclarer une restauration/vente/publication réussie sans preuve.
9. Préserver tous les artefacts sources utiles ; préférer archiver/dédupliquer à supprimer.
10. Si du travail autonome reste possible, le poursuivre jusqu'au prochain vrai verrou humain.
